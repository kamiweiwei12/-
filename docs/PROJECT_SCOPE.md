# 项目范围与阶段门禁

状态：`FROZEN v1.0`，2026-11-26。

## 1. 产品目标

“雪野营地”是单营地、四季运营的课程设计系统。季节不是全局开关；资源开放、价格、活动、库存和运营状态均按日期独立生效。系统用统一用户、订单和资源占用模型支撑住宿、日营、滑雪、缆车和装备业务。

## 2. 第一阶段冻结边界

本阶段只完成调研、需求、架构、ER/关系模式、公共契约、协作规范和测试计划。不得开发完整业务、不得创建最终大批量表、不得把草案迁移合并到 `develop`。

## 3. 建议的交付优先级

原始指令把32项业务都列为 P0，对两人、约五周的课程设计存在明显范围风险。为保证可运行和可验证，建议把交付门禁拆为：

### P0-A：必须先闭环（评分主线）

- 注册、登录、顾客/管理员权限。
- 营地、资源类型、具体住宿/营位资源和开放规则。
- OVERNIGHT 与 DAY_PASS 时间语义。
- 可解释价格规则、每日价格预览和成交快照。
- 空闲查询、创建订单、模拟支付、取消、资源释放。
- PostgreSQL 范围排斥、事务、触发器、函数/过程、视图和索引。
- 住宿并发抢订和查询优化证据。
- 顾客预订主流程、我的订单、管理端房态/价格日历。

### P0-B：在 P0-A 稳定后接入同一订单

- 滑雪票产品、票务时段容量、滑雪课程场次及容量。
- 缆车时段容量、核销与实际客流。
- 装备型号、批量库存、单件资产、租赁、取还和维修。
- 票务/装备并发测试与基础统计。

### P1：有余力再做

- 二维码图形（P0 先用核销码文本）。
- 天气预警模拟、候补、损坏检查、更丰富图表和审计页面。

### P2：本次不做

- 真实支付、真实天气、AI定价/推荐、地图、短信、邮件、积分、微服务、Redis、消息队列。

## 4. 成功标准

- 全新环境可按 README 启动，Flyway 从空库成功迁移。
- 主要操作产生真实数据库写入，状态和金额可追溯。
- 同一住宿资源无有效订单时间重叠；有限容量不超卖；库存不为负。
- 订单取消只释放该订单真实持有的占用，重复调用不重复释放。
- 价格修改不改变历史成交快照。
- 有正常、边界、异常、并发和性能测试的真实证据。

## 5. 非目标

- 不模拟真实大型度假集团、多租户、会计总账或OTA渠道。
- 不为表数量和技术数量评分而创建无业务含义对象。
- 不追求生产级支付与高可用基础设施。

## 6. 已确认的范围决策

1. 采用P0-A/P0-B门禁，先完成住宿与数据库评分主线。
2. 一张订单允许多个住宿资源，并可混合套餐和单独商品一次付款。
3. 滑雪票赋予入场资格，缆车预约单独占时段容量。
4. 滑雪课程属于P0-B，不阻塞首个住宿演示闭环。
