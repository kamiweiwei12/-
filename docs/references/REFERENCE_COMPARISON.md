# 五个参考项目比较与采用决策

核查日期：2026-11-25。研究副本位于临时目录，不进入本项目仓库。

## 证据等级

- A：README、源码/迁移和测试相互印证。
- B：源码存在，但自动测试不足或实现有明显缺口。
- C：仅README声称，源码未确认或相反。

## 比较矩阵

| 项目 | 栈/数据库 | 许可证 | 源码确认强项 | 局限 | 等级 |
|---|---|---|---|---|---|
| Ski Resort Database | MSSQL SQL脚本 | MIT | 票有效期、租赁取还、视图、事务过程、场景脚本 | 仅4表；无库存/缆车容量/自动测试 | B |
| Louez | Next.js/TS, Drizzle, MySQL | AGPL-3.0 + 资产例外 | 批量与单件库存、维修停机、取还检查、丰富测试 | 技术栈/规模不符，直接复制许可风险高 | A（所核模块） |
| StayGrid | Spring Boot/JPA, PostgreSQL | MIT | 每日库存、悲观锁、策略链 | 无Flyway；几乎无测试；节假日硬编码、公式风险 | B |
| OpenStays | React/Convex | MIT | 半开夜晚、hold冲突、季节价、取消、对抗测试 | 非关系数据库，嵌套结构不满足本项目3NF目标 | A（自身栈） |
| Ski Station System | React/.NET/EF, PostgreSQL | 未发现 | 只有Ticket CRUD和单迁移 | README与实现差距大，无测试/许可证 | C |

## 采用的设计

1. 从 Ski Resort Database 采用“票有效区间、岗位视图、事务过程”的业务表达。
2. 从 Louez 采用“装备型号/具体资产/停机区间/分配/检查”的概念分解。
3. 从 StayGrid 采用“价格策略分步解释、容量库存行锁”的方向，但修正公式并以Flyway建模。
4. 从 OpenStays 采用“本地日期、半开住宿夜、hold/过期/取消、对抗测试”。
5. PostgreSQL官方范围类型与排斥约束作为住宿/单件资产并发最终防线。

## 舍弃的设计

- 不复制任何项目的完整代码、UI或图片。
- 不采用真实支付、AI、OTA、短信、邮件、多租户和复杂SaaS模块。
- 不采用 JPA/ORM 自动DDL、Convex嵌套schema或 MySQL 特有实现。
- 不把 README 功能列表当作实现证据。
- 不用多个平行业务订单表；采用统一订单+类型明确占用表。

## 本项目原创组合

```text
统一订单/价格快照
  ├─ 住宿与单件资产：PostgreSQL排斥约束
  ├─ 票/课程/缆车/批量装备：容量行FOR UPDATE
  ├─ 装备：型号 + 资产 + 维修区间 + 库存流水
  └─ 核销：令牌哈希 + 单次状态 + 事件日志
```

该组合不是任一参考项目的直接移植；它针对课程评分中的3NF、事务、并发、触发器/过程/视图、索引与可验证测试重新设计。
