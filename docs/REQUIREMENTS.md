# 系统需求说明

状态：`FROZEN v1.0`。

## 1. 参与者

- 游客：浏览营地、资源、价格和活动。
- 顾客：注册登录、搜索、下单、模拟支付、取消、查看订单与核销码。
- 运营管理员：管理资源、开放日期、价格、订单、票务、缆车、装备、核销和统计。
- 系统任务：过期待支付占用、生成统计视图结果；不得绕开同一业务服务直接篡改订单。

课程范围暂不细分前台、教练、维修员等账号；通过管理员操作留痕表达岗位行为。

## 2. 核心功能需求

### FR-A 用户和权限

- 邮箱唯一注册，密码只保存强哈希。
- JWT 访问令牌；管理接口执行服务端角色检查。
- 顾客只能查看和操作自己的订单；管理员可按权限操作运营数据。

### FR-B 资源与开放

- 营地拥有资源类型和具体资源，类型包括草地、平台、房车位、民宿、木屋。
- 每个具体资源有容量、状态和支持的住宿模式（OVERNIGHT/DAY_PASS）。
- 维修、停用或不在开放规则内的资源不可预订。
- 系统不进行全站季节切换；季节仅作为日期规则和价格规则的分类条件。

### FR-C 搜索与价格

- 按住宿模式、日期/时段、人数和类型查询真实可用资源。
- 价格由基础价和匹配规则组成；特殊日期 > 节假日 > 季节/周末 > 基础价，具体组合方式见数据库契约。
- 后端返回逐日/时段价格解释；创建订单时重新计算，不接受客户端总价。
- 订单保存成交价及规则快照，历史订单不随规则变化。

### FR-D 订单与模拟支付

- 一张订单可以包含多间住宿、多个票务/课程/缆车/装备项以及套餐组件。
- 每间具体住宿形成独立订单项与占用记录；套餐与单独选购可混合进入同一购物车。
- 一张订单只结算一次；创建全部订单项和资源占用必须原子成功或整单失败。
- 创建订单和全部资源占用必须在同一事务完成；任何一步失败全部回滚。
- 模拟支付可成功/失败，成功请求幂等；不得调用真实支付网关。
- v1只支持整单取消和模拟整单退款，并原子释放全部尚未履约占用；重复取消不重复释放。
- 每个订单项独立记录履约状态，整单状态由明细聚合。

### FR-E 滑雪票、课程和缆车

- 票种/课程/缆车时段均有日期、容量、价格和运营状态。
- 票务或课程预订占用对应时段容量；滑雪票核销与缆车具体时段预约分离。
- 核销码只可成功使用一次，重复核销返回业务冲突；保留核销日志。
- 缆车统计区分“预约人数”和“实际核销人数”。

### FR-F 装备

- 装备型号决定规格和价格；可按批量数量或单件资产追踪。
- 单件资产在重叠租期内只能被一个有效订单占用，维修期不可租。
- 批量库存的有效重叠占用量不可超过可租总量。
- 取件、归还、维修改变资产/租赁状态并记录库存流水；不直接覆盖历史记录。

### FR-G 管理与统计

- 管理员维护价格日历、资源、时段容量和装备状态。
- Dashboard 至少显示收入、订单量、住宿入住率、票务/缆车核销和装备利用率。
- 统计必须由真实业务表/视图产生，口径在页面和报告中说明。

## 3. 非功能需求

- 一致性：不重复预订、不超卖、不出现负库存、金额快照可追溯。
- 性能：常用列表分页；查询在课程规模数据上有 `EXPLAIN ANALYZE` 证据。
- 安全：参数化 SQL、密码哈希、服务端授权、输入校验、秘密不入库。
- 可维护：Flyway迁移、统一契约、分层代码、清晰枚举和错误码。
- 可用性：响应式；具有 Loading/Empty/Error/Success、分页、搜索和校验。
- 可复现：Docker Compose/README 可在干净环境恢复数据库与应用。

## 4. 关键业务规则

- 所有占用区间为半开 `[start_at,end_at)`；相邻退房和入住不冲突。
- `end_at > start_at`；DAY_PASS 必须在同一营地业务日内，OVERNIGHT 至少跨一个住宿夜。
- 只有 `PENDING_PAYMENT/CONFIRMED/IN_USE` 订单占用资源；取消、过期、完成不占用未来库存。
- 订单总额等于明细小计之和；货币固定 CNY；数据库统一两位小数。
- 含套餐时，订单总额等于明细小计之和减套餐优惠快照，且不得为负。
- 订单过期后不能支付；过期占用由幂等服务释放。
- 核销、模拟支付、取消必须防重复请求。

## 5. 验收场景

1. 两个并发顾客预订同一木屋重叠日期，只能一个成功。
2. 20张票剩余时50人并发购买，成功总量不超过20。
3. 维修中的雪板资产不出现在可租列表。
4. 修改元旦价格后，已支付订单价格不改变，新订单使用新规则。
5. 取消订单后对应资源可再次预订；再次取消无额外库存流水。
6. 普通顾客访问管理端价格接口返回403。
7. 同一订单预订多间房并混合装备/票务时，只产生一次付款；任一项目冲突则整单无残留。
